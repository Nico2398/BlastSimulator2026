# 3D Models

Every mesh the player sees is generated by Blender from Python. Nothing is hand-modelled, so any model change starts in a `.py` builder and ends with three files committed together.

## The pipeline

```
assets/models/blender/<family>.py   source of truth — edit here
        │  npm run models:build [-- <id|category> …]
        ├─► assets/models/blend/<id>.blend   editable snapshot, modifiers live
        └─► public/models/<id>.glb           the asset the game loads
```

| File | Role | Committed |
|------|------|-----------|
| `assets/models/blender/*.py` | Generator. Deterministic: rebuilding reproduces the asset byte for byte | yes |
| `assets/models/blend/<id>.blend` | Blender file for hand iteration, modifiers unapplied | yes |
| `public/models/<id>.glb` | What the browser fetches and what the tests parse | yes |

`build.py` holds the registry that routes an id to its builder. Vehicles: `_t1` → `vehicles_t1.py`, `_t2` → `vehicles.py`, `_t3` → `vehicles_t3.py`. Buildings: `buildings_t1.py` / `buildings_t3.py` when they define the type, else `buildings.py` for every tier. Workers → `workers.py`, props → `props.py`.

Buildings read their footprint from `building-defs.json`, dumped from the game's own `BuildingDefs` by `npm run models:defs` (which `models:build` runs first), so both sides agree on size.

## ▶ PROCEDURE — change an existing model

1. Find the builder: the id's prefix and tier name the module through `build.py`'s registry.
2. Edit the Python. Shape helpers and modifiers: `references/blender-helpers.md`.
3. Rebuild that id alone: `npm run models:build -- <id>`. Needs Blender as a Python module (`pip install bpy`, ~1 GB, once). When `bpy` is unavailable, state the model channel is blocked rather than hand-editing a `.glb`.
4. Prove the contract: `npm run test -- ModelAssets` — ids exist, parse, fit the budget, carry their nodes, tints and bounds.
5. Look at it: `npm run dev &` then `npm run models:preview -- <id>`, and **open every PNG with the Read tool**. The viewer draws through the game's own `SceneManager`, so what it shows is what the player gets.
6. Anything a player sees in place — a building on its footprint, a vehicle beside a worker — also needs an in-game capture (`dev-visual-testing`).
7. Commit the `.py`, the `.blend` and the `.glb` in one commit.

A `.py` edit without a rebuilt `.glb` changes nothing the game or the tests can see: `ModelAssets.test.ts` parses the committed binary, not the source.

## ▶ PROCEDURE — add a model

1. Name it from the catalog, not by hand: `ModelIds.ts` derives `worker_<role>`, `vehicle_<role>_t<tier>`, `building_<type>_t<tier>`, `prop_<kind>_<variant>` from the core catalogs. A new role or tier that exists in core needs a builder and nothing else.
2. Write the builder in the module its family lives in; register it (`registry()` for props and buildings, `ROLES` for workers and vehicles).
3. Add it to `allModelIds()` if it is a new *kind* of asset, so the loading screen preloads it.
4. Give the renderer a fallback size where it instantiates the model — a missing asset must cost one stand-in box, never the level.
5. Extend `ModelAssets.test.ts` with what the new family guarantees (nodes, tints, height, footprint).
6. Then follow the change procedure above from step 3.

## Art direction

**Cartoon, not low-poly.** Curves are round, edges are bevelled, shapes are soft. A low triangle count is welcome as an outcome, never as a look: faceted silhouettes and hard corners read as unfinished, not stylised.

- Round the world: `bevel()` every hard edge (3–4 segments), smooth shading with `mark_sharp()` keeping real creases. Spheres, capsules and torii over boxes wherever a shape allows.
- Exaggerate function. Big head, small body. Fat tyres, oversized bucket, chunky hard hat. The part that does the job is the part that reads.
- Silhouette first. The gameplay camera sits far above; a joke or a feature that only exists as surface detail is invisible. Model it as a shape or leave it out.
- Detail thinner than ~3 cm disappears under the outline hull. Below that, merge it into its parent shape.
- Colour lives in material slots. The exporter writes no UVs and no images — there are no textures to hide behind, so a colour break is a material, a face selection (`assign_by`) or a separate part.
- Faces have eyes. Workers get big whites, offset pupils, a highlight and brows; that is what makes them minions rather than mannequins.
- Judge in the game's pipeline (`models:preview`), never in a Blender viewport render. The toon ramp is three flat bands plus a near-black outline: a shape that only reads under smooth studio lighting does not read in the game.

## ▶ Tiers carry the satire

The game is a satire of extractive capitalism, and the equipment tells the joke. Each tier is **its own model** — never a scaled, recoloured or decorated copy of another.

| Tier | Reads as | Rules |
|------|----------|-------|
| 1 | Improvised junk that barely works | The wrong tool pressed into service: a dumpster, a shopping trolley, a wheelbarrow, a garden shed, an outhouse. Patched, dented, rusted, taped, mismatched, propped on bricks. 60–85 % of the tier-2 footprint; buildings stay under 2.8 m and overhang by at most 0.8 m. |
| 2 | The honest machine | What the equipment would plainly look like. Clean, functional, no jokes and no luxury. This is the reference the other two tiers deform. |
| 3 | Corporate excess | Gold trim, chrome, neon and emissive glow, and one absurd add-on that has nothing to do with the job: a rooftop infinity pool, a helipad and a limousine, a skull cab, a castle moat, a gantry crane still adding crates. Tallest and heaviest of the three. |

Existing caricatures to stay consistent with: the Dumpster on Wheels, Pokey McPoke, The Scratch, The Cells, the Think Tank Tent, the Boom Closet; the Mega Mover XL, the Rock Reaper, the Helldriller, the Unnecessarily Luxurious Hotel, Corner Office Supreme, Fort Kaboom, Hoarder's Paradise. Full list with builder modules: `references/model-catalog.md`.

The joke has to survive the game camera and the tier test: a building must be taller than the tier below it, and no model may swallow its neighbours' cells (footprint + 2.2 m).

## The runtime contract

Break one of these and the model loads but misbehaves — a vehicle drives sideways, a worker's arms stop swinging, a wall stops taking its type colour.

| Convention | Rule |
|------------|------|
| Scale | 1 Blender unit = 1 game unit = one voxel. Blender is Z-up; the exporter converts to glTF Y-up |
| Origin | Ground contact at z = 0. `bounds.min.y ≈ 0` is asserted |
| Facing | Workers and vehicles face **+X**; the renderer yaws the root toward travel. Buildings are centred on their footprint, doors row at **+Y** (game −Z) |
| Animation nodes | Direct children of the scene root, and only those, are animatable: `Head`, `Torso`, `ArmL`, `ArmR`, `LegL`, `LegR`, `Wheel*`, `Flywheel`, `Body`. Build them with `pivot(name, location, parts)` — the Empty's location is the rotation pivot. Everything else lives under `Body` |
| Wheels | Pivot at the hub centre, axle along Blender **Y**. The renderer measures the rolling radius from the node's own bounds, so any wheel size turns true |
| Tint materials | A material named `Tint*` is cloned and recoloured per instance: `TintRole` (worker overalls and hat), `TintBody` (vehicle paint, building walls), `TintRock`, `TintGrass` (biome colours). Every model of its family must expose the one its renderer asks for |
| Emissive | A material with an emission colour stays its own mesh and glows. Use it for the tier-3 neon, beacons and lamps |
| Everything else | Merged into one vertex-coloured mesh per node. Plain colours are free; keep them in material slots, not geometry tricks |
| Props | One `Body` node, no animation nodes — they are drawn instanced. Trees and grass are bent by a height-based wind shader, so the base sits at the origin and the canopy above it |

How the export is consumed — merge buckets, per-instance tints, instancing, the sway shader — is in `references/runtime-contract.md`.

## Performance

Budget by **how many copies are drawn**, not by how important the model feels. A worker at 10 k triangles is cheap because a level holds dozens; a tree at 10 k would be ruinous because a level plants thousands.

| Family | Copies per level | Triangles (measured) | Notes |
|--------|------------------|----------------------|-------|
| Workers | tens | 9.7 k – 10.5 k | 13 merged meshes each |
| Vehicles t1 / t2 / t3 | tens | 5.8 k – 11.4 k / 9.6 k – 11.1 k / 12.1 k – 17.6 k | tier 3 is the heaviest by design |
| Buildings t1 / t2 / t3 | tens | 3.5 k – 6.7 k / 3.2 k – 6.3 k / 7.2 k – 13.2 k | 3 merged meshes each |
| Trees (near) | thousands | 84 – 1 292 | test ceiling 1 600 |
| Trees (far LOD) | thousands | 8 – 154 | test ceiling 220; `finish_far` decimates to 12 % |
| Grass tufts | up to 9 000 | 64 – 96 | drawn without an outline hull |
| Flowers / bushes | 1 200 / 900 | 340 – 664 / 640 – 960 | instance ceilings thin them by an even stride |
| Rocks, houses | hundreds | 1 280 / 216 – 348 | |
| `prop_twister` | a handful | 5.8 k | not instanced |

File budget, asserted by `ModelAssets.test.ts`: **≤ 400 KB per `.glb`**, ≤ 4 MB gzipped across every asset (what a host actually serves), ≤ 16 MB raw. Current set: 92 models, 10.2 MB raw, 1.9 MB compressed.

Where the triangles go:

- Segment counts are the biggest lever. A 32-segment cylinder on a 3 cm bolt is waste; 8–12 is plenty on anything small. `sphere()` defaults to 32 × 16 — drop it for small parts.
- `bevel(width, segments)` multiplies edge geometry. 2 segments on small parts, 3–4 on the shapes that carry the silhouette.
- `subsurf()` quadruples per level. Prefer bevel plus smooth shading; reach for subdivision only where a shape genuinely needs it.
- Bake curvature into the outline rather than subdividing to bend it — the grass blade's curved 2D profile costs a fifth of a straight blade bent by a modifier.
- Draw calls follow materials, not parts: one merged mesh per node, plus one per `Tint*` material, plus one per emissive colour, plus one outline hull. An extra plain colour is free; an extra tint or glow colour costs a draw call on every instance.
- Anything instanced by the thousand skips the outline below about a metre on screen — a sub-pixel line only darkens the frame.

## ▶ Verification

| Channel | Command | Proves |
|---------|---------|--------|
| logic | `npm run test -- ModelAssets` | Every catalogued id exists, parses, fits the size budget, carries its nodes, tints, ground contact, tier heights and footprint |
| visual | `npm run models:preview -- <id>` then Read the PNGs | The model reads through the game's toon ramp, outline and shadows |
| visual | `npm run screenshot -- --name <n> --commands "…" --focus-entity "…"` | The model reads in place, at the game camera's distance, beside its neighbours |
| static | `npm run typecheck` | Only when TypeScript changed alongside the asset |

`npm run test` runs ~500 s — detach it through `npm run long -- start models npm run test` and wait it out in the same turn. Capture rules, focus flags and the model-viewer URL parameters: `dev-visual-testing`.

A model change is unverified until an image has been inspected. A green `ModelAssets` run proves the contract, not the picture.

## Editing a `.blend` by hand

The `.blend` files exist for hand iteration, and the next `models:build` overwrites them. So: open `blend/<id>.blend`, edit, export with **File → Export → glTF 2.0** to `public/models/<id>.glb` (format glb, +Y up, apply modifiers, no UVs, no images, no animations), then **port the change back into the Python builder** and rebuild. A hand edit that never returns to the source is lost at the next build.
