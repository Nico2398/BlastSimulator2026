## What ships

Sampled one-shots (`public/audio/sfx/*.mp3`, 79 mono files, about 620 KB; mostly CC0 plus eight CC-BY files from six OpenSFX sounds) layered with generative sounds rendered in code at startup (blast snap/sub/tail, warning beeps, siren, thunder, wind, rain, machinery bed, the reverb impulse). Samples carry realism, synthesis carries what no bank has (a tuned siren, seamless weather beds, a blast tail). No music tracks yet: the architecture exists and `MUSIC_TRACKS` is empty.

**Credits reach players.** Settings, under the volume sliders, has an "Audio credits" button (`AUDIO_CREDITS_ACTION` in `SettingsPanel`). It opens `AUDIO_CREDITS_URL` (`/audio/credits.html`, `src/core/config/audio/ui.ts`) in a new tab with `noopener`. `public/audio/credits.html` is a plain static page that fetches and shows `CREDITS.md` (the generated file) beside it; it is hand-written, so touch it only if `CREDITS.md` moves.

**Pending, state it honestly when asked:**
- No music tracks; Settings has no Music slider until the first track (the `music` bus and its default volume exist). No main-menu ambience.
- Nobody has listened to any of it (see "What no channel proves").
- **Licence evidence is incomplete.** 31 of the 79 files have a layer taken from the community mirror (Kenney Impact, Sci-Fi, RPG, Jingles and Interface packs, the OpenGameArt pack) and rest on the mirror's own record that each pack page says CC0. Only one mirror file, which the game does not use, was ever compared with Kenney's own repository. Nobody on the project has fetched the pack pages or compared those files with the official downloads. Say "rests on the mirror's record", never "verified", until the owner runs the one-step check on a networked machine: download the official packs (URLs in `public/audio/CREDITS.md`), unzip them into one folder and run `python3 assets/audio/build.py --sources <dir> --verify-upstream <folder>`. It prints MATCH / DIFFERENT / NOT FOUND per mirror file and exits 1 unless every file matches; then confirm "License: Creative Commons CC0" on each pack page and record the result in `assets/audio/credits.template.md`. `--selftest` runs the helper offline on a generated fake tree (it has never run against the real downloads).

## Module map and data flow

```
SOUND_CATALOG (src/audio/SoundCatalog.ts: every sound, one table)
   -> AudioEngine (preload: SampleBank decodes mp3, SynthBank renders recipes) -> SoundPlayer -> AudioManager graph
   -> implements AudioPlayer (src/audio/AudioPlayer.ts: play / loop / duck / setListener) or NULL_AUDIO_PLAYER
   -> directors only ever see AudioPlayer:  ui/ (DOM + commands)   director/ (world)   music/ (own streaming path)
   -> src/main.ts + a few injected hooks in src/ui and src/renderer call the directors
```

- `src/audio/AudioManager.ts`: owns the AudioContext, bus graph, volumes, ducking and the hidden-tab suspend/resume (it follows `visibilitychange` by itself). Works without Web Audio (volumes still stored, Settings still works). **There is no mute API**: `setMuted`, `isMuted` and `suspend` were removed because nothing called them; the master slider at 0 is the only silence. Do not add one back without a caller and a Settings control.
- `src/audio/AudioEngine.ts`: the facade. Three preload tiers (`planPreload`): tier 1 is every sample of a `ui`-bus sound plus every sample of a sampled sound with priority >= 3 (`PRELOAD_CONFIG.essentialPriority`) and flipping it sets `ready`; tier 2 is the remaining samples; tier 3 is the synth recipes and the reverb impulse. **`ready` excludes every synth cue** (blast snap, sub, tail, beeps, siren, thunder, weather and machinery beds): they can be missing for the first second or two, and a play before then is dropped silently; `preloaded` says everything was tried. A failed fetch or decode is retried once after a 250 ms backoff (`SAMPLE_BANK_CONFIG`), then listed in `failedAssets`; a preload that dies unexpectedly adds `'preload'` there. Never rejects.
- **Startup cost, measured in Chromium:** the synth renders are nine main-thread stalls of 70 to 105 ms each (rain, wind and snap are the heavy ones). One variant renders atomically, so `SYNTH_RENDER_CONFIG.sliceBudgetMs` only spaces the stalls apart, it does not shorten them. Rendering in a Worker is the known improvement and is not done.
- `src/audio/engine/`: `SoundPlayer` (voice graph, variant pick, pitch/level jitter, re-arming of beds that lost their voice), `Voice`, `VoiceBudget` (cooldowns, per-sound caps, global cap with priority stealing), `cooldown` (`CooldownGate`, the one cooldown implementation: the voice budget runs it on milliseconds, the director's cue gate in `director/rateLimit.ts` on seconds), `spatial` (distance, pan, air absorption, the reference and cull distances the director reuses), `ducking`, `LoopBed`, `softClip`, `preloadPlan`.
- `src/audio/synth/`: pure deterministic DSP, runs in Node. `recipes.ts` is the table; `sounds/*` are the recipes; `finish.ts` brings every render to the level convention.
- `src/audio/director/`: `GameAudioDirector` composes `EventFeed` (core events), `StateDiffFeed` + `worldDiff` (state changes), `WorkSounds` (work bursts + machinery bed), `BlastAudio` + `blastPlan` + `blastLosses` (blast timeline), `EvacuationSiren`, `Ambience` (weather beds, thunder), `DistantLife`, `LevelStings`; `BedFeed` is the one rule for driving a loop bed from a director (send a level only when it moved by an epsilon, always send the final zero). Depends on `AudioPlayer`, the core `EventEmitter`, `GameState` and the event pool's `getEventById` (the category of an event for its stinger). It is handed the command already parsed (`ParsedCommandLike`), so nothing under `src/audio/` imports `src/console/`; `src/core` never imports `src/audio`.
- `src/audio/ui/`: `installUiSounds` + `uiTone` (one capture-phase DOM delegation: every control gets a sound), `UiCues` (chokepoints the DOM cannot see), `commandCues` + `commandCueTable` (console command -> cue), `CommandClaim` (command cue suppresses the generic click), `audioUnlock` (resume on the first gesture the browser accepts), `safePlay` (fenced playback; the first fault is logged once, never rethrown).
- `src/audio/music/`: `MusicCatalog`, `resolveMusicTrack`, `musicContext`, `MusicPlayer` (streamed, equal-power crossfade), `MusicDirector`.
- `src/audio/debug/` (`?audioLog=1` play log), `src/audio/lab/` (logic of the sound lab and the offline mixes).

**main.ts hooks:** `AudioEngine` is built only outside `?scenarioMode=1` (scenario runs get the null player, no fetch, no decode, no music; the manager and its suspended context still exist); the UI and director layers are still built on the null player so their handlers run. `installAudioUnlock` (`src/audio/ui/audioUnlock.ts`) resumes the context and starts waiting music on every `pointerdown`, `pointerup`, `click`, `touchend` and `keydown`, and **keeps its listeners until the context is actually running** (Escape, `touchstart` and a `pointerdown` that becomes a scroll are not activations in every browser, so one gesture is not enough); with no Web Audio at all the first gesture detaches them. `runGameCommand` parses the command once, then calls `commandCue` and `gameAudio.onCommand({ parsed, ... })` once per command; the frame callback calls `gameAudio.update` (real seconds, listener from camera target + ground-right + distance, never the shaken camera) and `music.update`; the renderer's blast callback calls `gameAudio.onBlast` + `music.duck`; `setLightningHandler` calls `onLightning`; skipping or seeking blast playback calls `cancelBlast`. `UIManager.setUiCues` forwards `UiCues` to panels, `NotificationCenter`, `ConfirmModal`, `SettingsPanel`; selection and `PlacementController.setRefusedHandler` call `UiCues`. `tests/unit/lint/MainAudioWiring.test.ts` guards these call sites by source text.

**One owner per sound.** `commandCue` voices orders, hire, fire, purchase, order-time build, denials (`ui_denied`, the only refusal sound: `ui_error` was removed, nothing played it), time and confirm cues. The director voices what only state or a core event shows:
- state diff (`worldDiff`): building_built, vehicle_start of a new vehicle, building_demolished and vehicle_scrap of an entity that vanished outside a blast, drill_done, charge_loaded, survey_done, order_done, coins for contract and bonus income (not sales, upkeep or refunds), level stings (re-armed when a won level is reopened by "keep playing"). It plays nothing for casualties.
- core events (`EventFeed`): hauling, vehicle_start on mounting, the horn of a stuck vehicle, worker_collapse (`employee:collapsed`), level_up, unlock, shift_bell.
- the whole blast (`blastPlan`): snap, sub, crack, boom, tail; the debris rain, built only from fragment flights that visibly move (`isAnimatedFlight`: rock that never leaves its place makes no sound); secondary explosions; building_demolished for the buildings the report lists plus those flyrock or a secondary blast destroyed; vehicle_scrap for vehicles destroyed by the blast; duds; one muted `notify_bad` for casualties. The destroyed buildings and vehicles are found from the report's `building_destroyed` and `vehicle_destroyed` accidents and placed where the last world snapshot saw them (`blastLosses`), because the entities are gone by the time the blast is played. A diff that lands with a blast report (`blastLanded`) plays no demolish or scrap cue of its own.
- weather (`Ambience`): beds follow the weather at most once per `AMBIENCE_CONFIG.minDwellS` (6 real seconds) so 8x does not retarget them several times per fade, except from no weather at all, which they take at once. Storm rumbles count storm time: the first comes 2 to 6 s into a storm, later ones every 8 to 20 s, a calm shorter than `rumbleResetCalmS` (20 s) between two storms does not restart the clock, and a pause or a menu freezes it.
- the pre-roll dip (ambience ducked, work sounds quiet) is held from the start of the blast job until the flash fires, renewed every `preRollDuck.refreshS` and released at `maxHoldS` if the flash never comes.

Toasts for director-voiced events are created `silent: true`. Grep a sound id for existing callers before adding another.

## Bus graph and levels

```
voice: source -> [lowpass -> pan, if spatial] -> gain -> bus (volume -> duck) -> master gain
       -> compressor (-3 dB, 20:1) -> soft clipper (knee 0.8, ceiling 0.97) -> destination
       gain -> reverb send -> wet lane of the same bus (volume -> duck) -> convolver -> return -> master
```

**Master chain.** The compressor applies the Web Audio spec's automatic makeup gain (about +1.7 dB, a factor of 1.22 measured in a Chromium offline render), so the clipper's effective knee is about 0.66 at the limiter input (0.8 / 1.22), not 0.8. Measured through the real chain: input 0.1 gives 0.122, 0.5 gives 0.609, 0.66 gives 0.804, 1.0 gives 0.872 (about -1.2 dBFS). The clipper is a safety net, not part of the sound: gain-stage the mix to stay under the knee, and read `drive %` of `npm run sounds:check` (share of samples above the knee) as the over-boost guard, since the final peak can no longer exceed the ceiling.

Buses: `effects`, `ambient`, `ui` (catalog `SoundBus`) and `music` (MusicPlayer only), plus master. Each bus has a dry and a wet lane so a slider or a duck scales the reverb tail with the sound.

**Level convention.** Every sample is normalised to -18 dBFS gated RMS, -1 dBFS peak ceiling; every synth one-shot is rendered to the same; every loop to -26 dBFS (`SYNTH_LEVELS` in `src/core/config/audio/synth.ts`). Catalog `gainDb` is the trim against that reference: 0 means an ordinary effect. Spiky files (coins, till, hammer) land under -18 and carry a positive trim. The blast layers (snap, crack, boom, sub, tail) stack within 30 ms and are trimmed together: re-measure with `npm run sounds:check` after touching any of them or `BLAST_AUDIO_CONFIG.maxBoostDb` (3 dB today), and read the blast mix's `drive %`, not its peak.

## Adding things

**Sampled one-shot.** (1) Add the sound to `sounds` in `assets/audio/recipe.json`: `kind` (`ui`, `work`, `sting`, `blast`: sets the length cap), `layers` (`pack`, `file`, optional `start`/`dur`/`at`/`gain_db`/`af`); the pack must exist under `packs` with its licence. (2) `python3 assets/audio/build.py --sources <dir> --only <name> --report` (needs Python 3, numpy, ffmpeg and a local copy of the upstream packs laid out as `packs[*].dir`; not in the repo). Output is deterministic, mono 44.1 kHz mp3 in `public/audio/sfx/`. (3) `python3 assets/audio/build.py --credits` regenerates `public/audio/CREDITS.md` from `assets/audio/credits.template.md`; never hand-edit it. (4) Add the catalog entry with `sample('<name>')`. A pack taken from a mirror needs `mirror` and `official_zip` in `packs` so the credits list its official download. `tests/unit/audio/AudioAssets.test.ts` fails on a file the catalog does not name, a catalog name with no file, a file missing from the recipe or the credits, a non-CC0/CC-BY licence, a length over the cap or a byte-identical duplicate.

**Synth sound.** Recipe module in `src/audio/synth/sounds/` (a `SynthRecipe`: `variants`, `loop`, `render(variant)`, pure and deterministic, seeded through `rngFor`), ending in `finishRender(raw, sampleRate, 'oneShot' | 'loop')` so it lands on the level convention. Every number goes in `src/core/config/audio/synth.ts`. Register it in `SYNTH_RECIPES` and the `SynthRecipeId` union in the catalog, then add the catalog entry with `synth('<id>')` (`loop: true` for a bed, played through `AudioPlayer.loop`). Each render carries its own `sampleRate`. `tests/unit/audio/synth/` checks level, seams and character.

**UI cue.** Prefer no code: `installUiSounds` infers the tone from the element (`bsx-btn-primary`, `bsx-btn-danger`, `bsx-btn-locked`, `aria-pressed`, `data-lang`, disabled state). Override with `data-sfx="<cue>"` (set allowed in `src/audio/ui/uiTone.ts`) or `data-sfx="none"` on the control or an ancestor. A command-backed action: add the verb to `COMMAND_CUES` in `src/audio/ui/commandCueTable.ts`, or to `SILENT_COMMANDS` with the reason; a test fails when a registered verb is in neither. Failed commands play `ui_denied` (the one refusal sound); `scripted: true` commands (tutorial) play nothing; `tick` is always silent. A chokepoint the DOM cannot see gets a named `UiCues` method called from an injected hook. A new pickable kind needs a pitch in `UI_SELECTION_PITCH_CENTS`. No player-visible string is involved, so no i18n.

**World cue.** Core code emits an event or changes state; it never calls audio. Pick the feed: a core event -> `EventFeed` (`subs.on`, intent -> sound in `ENTITY_CUES`/`FLAG_SOUNDS`, policy in `EVENT_CUES`/`FLAG_CUES`); a state change -> `src/audio/director/worldDiff.ts` with its cooldown in `DIFF_CONFIG`; a work site -> `WorkSounds`; the blast -> `blastPlan`; weather -> `Ambience`. Play one-off cues through `playCue` (range check, cooldown, then the player) and give positional cues a `site` so they pan and attenuate.

**Music track.** Drop the mp3 in `public/audio/music/`, add one entry to `MUSIC_TRACKS` in `src/audio/music/MusicCatalog.ts` (scope `menu`, `game`, `biome` or `level`; most specific wins; the biome is the declared `GameState.mineType`), follow `public/audio/music/README.md` (mastering, loop seams, size), credit the file through `assets/audio/credits.template.md`, run `npx vitest run tests/unit/audio/music`. `MusicCatalog.test.ts` feeds `MUSIC_TRACKS` to `musicTrackProblems(tracks, context)` (`tests/helpers/musicCatalogChecks.ts`), a pure function that returns one line per problem (empty or duplicate id, file that is not a bare basename, mp3 missing from `public/audio/music`, unknown biome or level id). The catalog is empty today, so that test alone cannot fail; `musicCatalogChecks.test.ts` proves every rule on bad fixtures. Extend the function, not a loop in the catalog test, when a rule is added. With the first track also add the Settings row: `{ channel: 'music', labelKey: 'ui.settings.audio.music' }` in `AUDIO_CHANNELS` of `src/ui/panels/SettingsPanel.ts` plus the `ui.settings.audio.music` key in `en.json` and `fr.json`. Check the first track once in Chrome and Firefox: streamed element routing and autoplay recovery are only covered by fakes.

## Licensing

CC0 preferred. CC-BY allowed only when credited verbatim (author, title, source, licence link, "changes were made") in `public/audio/CREDITS.md`; today that is the OpenSFX group (eight files from six sounds, credited by name in the README and CREDITS.md, and shown to players by the Settings "Audio credits" button). Never CC-BY-NC, ND or SA, game rips, "free for personal use", GPL, or anything without a verifiable licence page. A mirror is not first-party: verify against the author's own repository or the official download, and until `build.py --verify-upstream` has matched a mirror file say that it rests on the mirror's record (see "Pending"). The licence goes into `assets/audio/recipe.json` with the sound, so CREDITS.md is generated, never remembered.

## Real-time rate limiting

The simulation runs 1x to 8x as one synchronous `tick N` command per real second, so a whole crew's events arrive in one burst and anything scaled by game speed multiplies. Every limit is in **real seconds**, never ticks: `GameAudioDirector.update` advances its own clock by the frame delta (clamped); the engine's cooldowns use `performance.now`. Events only mark intents; one flush per frame plays at most `maxPerFlush`, nearest to the listener first, with a per-entity cooldown, a global `spacingS` per intent and a token bucket for hauling. A state diff spanning more than `maxCoalescedTicks` is a load or a skip and plays nothing. The engine counts a scheduled voice as busy from the `play()` call, so `BlastAudio` hands cues over 0.35 s ahead.

**Voice priority and cooldown keys.** `priority` is 1 (background) to 4. At the global cap (32 voices) a newcomer takes the slot of the oldest voice of strictly lower priority, so a priority-4 sound survives a full budget as long as something lower is playing; it is still dropped by its own `cooldownMs`, by its `maxVoices` (two `blast_beep` voices already playing) and when every active voice is priority 4. Looped beds (weather, machinery) run at priority 3 and the siren at 4, so only priority-4 sounds can take a bed's slot; `SoundPlayer.setListener` re-arms a bed that wants to play but lost its voice at most once per `VOICE_CONFIG.loopRearmIntervalMs` (1 s, per frame while a game is on screen), so a stolen bed comes back by itself. A catalog `cooldownMs` is a cooldown on the play's key (default: the sound id), so it does not apply to a play carrying its own `key`: the blast timeline keys every repeatable cue (`blast:rain:3`, `blast:dud:1`), and `debris_hit`, `debris_pebble` and `blast_dud` therefore have no `cooldownMs`; only `maxVoices` and the plan's bins and caps shape them. Do not add a cooldown to a sound whose callers pass keys and expect it to throttle. New world sounds need a number in `src/core/config/audio/game.ts` for each of these, and a crowding test case when they can fire in volume.

## Tools: what each proves

| Tool | Command | Proves |
|------|---------|--------|
| Audio unit suites | `npx vitest run tests/unit/audio` | Catalog consistency, engine voice rules, recipe levels and seams, which cue each feed/command/control requests and how often |
| Crowding tests | `tests/unit/audio/crowding/` (inside the suite above) | Real game scripts at 1x and 8x through the real directors and the real voice budget: sound counts per window stay under measured bounds |
| Wiring lint | `npx vitest run tests/unit/lint/MainAudioWiring.test.ts` | The main.ts call sites exist (source text, not behaviour) |
| `npm run sounds:check` | headless Chromium; reuses a dev server or starts its own | Every sample decodes, every recipe renders, and the loaded count equals what the preload plan expects (an asset that neither loads nor reports failure, or a missing file, fails); live context runs; three scenarios (ui-tour, blast, busy-mine) mixed offline through the real graph. Fails on NaN, silence, a peak above -0.1 dBFS (which the safety clipper makes nearly unreachable) and a clipper drive above `maxClipperDrive` (1 % of samples above the knee); warns from `warnClipperDrive` (0.25 %), on clips, DC, mono loss, drops. Measured drive today: ui-tour 0.002 %, blast 0.085 %, busy-mine 0.0002 %. Prints a `drive %` column; writes WAVs and `report.json` to a fresh private temp directory (or `--out`). Exit 0/1/2 (2 = could not run) |
| `npm run audio:smoke` | same browser setup | The real engine preloads with zero failures; real clicks on menu controls produce the intended cues once each; a scripted game under `?scenarioMode=1&audioLog=1` shows the cues the game intends (hire, build, drill, blast layers, ducks) |
| `/sound-lab.html` | `npm run dev`, dev server only | Audition every sound by bus, spatial distance/pan, beds, live blast and busy-mine, "Download mix WAV" |
| `assets/audio/build.py` | see above | Rebuilds samples and credits deterministically. `--verify-upstream <dir>` (needs `--sources`) compares each mirror file a sound uses with the official pack unzipped in `<dir>`: the owner's one-step legal check on a networked machine, never run yet. `--selftest` proves the helper offline on a fake tree |
| `?audioLog=1` | any page | `window.__audioLog` and `window.__audioStatus()` record every request |

## What no channel proves

How it sounds. Every tool here measures counts, timing, levels and graph structure; none hears. Whether a timbre is pleasant, a mix is alive but not crowded, a cue reads as the right thing (the lawsuit gavel, the mafia sting, the blast crack), a loop is fatiguing, or small laptop speakers reproduce a low rumble is a human listening pass, and that pass belongs to the owner. Never write that a sound "sounds good"; write which numbers and tests passed. The `visual` channel does not play audio. Browser-only behaviour (autoplay policy, `ended` on a source stopped before it starts, `pointerdown` on disabled controls, Safari) is covered by fakes or one headless Chromium only.

| Music fades and blast dip | `src/core/config/audio/music.ts` |
| Sound lab and `sounds:check` limits (peak, clipper drive warn/fail, silence) | `src/core/config/audio/lab.ts`; play log size in `src/core/config/audio/debug.ts` |
